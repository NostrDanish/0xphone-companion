# Improvement Deep-Dive — NostrDanish/0xphone-companion — 2026-10-21

FastAPI task gateway + Kotlin/Compose companion app. Gateway is tested (`tests/test_gateway.py`); Android side is a skeleton. No CI workflow present (no `.github/`).

## Top recommendations (ranked, with effort S/M/L)

1. **[M] Add the owner-auth gate — client endpoints are currently unauthenticated.** Verified in `gateway/app.py`: `POST /jobs`, `GET /jobs/{id}`, `POST /jobs/{id}/cancel`, and **`POST /jobs/{id}/approve`** take no token at all. Only worker register/revoke/audit/config (`X-Admin-Token`) and claim/complete (worker token) are gated. Anyone on the network can submit jobs, read other jobs' `result` (payload contents), cancel them, and — worst — *approve* `awaiting_approval` jobs, which is the human-in-the-loop spending decision for remote/paid routes.
   Design (owner-auth middleware):
   - One-time pairing: gateway prints a QR/6-digit code on first boot; app exchanges it for an `owner_token` (random 256-bit, stored hashed in `db.py` alongside workers).
   - FastAPI dependency `require_owner(x_owner_token: str = Header(...))` on all four client endpoints; approve/cancel should also verify the job belongs to the requesting owner once multi-user exists (single-owner now: just the token).
   - Compare with `hmac.compare_digest` — current `x_admin_token != expected` and `worker_token` lookups are fine at this scale, but admin compare should be constant-time (S fix inside the same change).
   - Keep 503-on-unconfigured behavior for `GATEWAY_ADMIN_TOKEN`; apply the same fail-closed pattern to the owner token.
2. **[S] Fix `android:usesCleartextTraffic="true"` in the manifest.** It is set unconditionally in `android/app/src/main/AndroidManifest.xml`. The gateway is HTTP-only today (dev on LAN, `http://10.0.2.2:8000` in `GatewayClient`), but shipping this lets every HTTP call from the app go cleartext on any network. Fix: `usesCleartextTraffic="false"` in main manifest + a `networkSecurityConfig` that permits cleartext **only** for debug builds / user-configured gateway host, and plan TLS (mkcert for dev LAN, real cert or a WireGuard/Tailscale-only bind for the phone↔gateway path) before any non-loopback use.
3. **[S] Gate the crash handler to debug builds.** `CompanionApplication.kt` installs a `Thread.setDefaultUncaughtExceptionHandler` unconditionally (comment says "Remove for release builds"). It shows the full stack trace in `CrashActivity` — a data leak (paths, tokens in messages) on a release device and a Play-policy problem. Fix: wrap registration in `if (BuildConfig.DEBUG) { ... }` and leave release to the default handler (or ACRA/Crashlytics later). One-line change; the BuildConfig field already exists.
4. **[S] Do not ship `GATEWAY_ADMIN_TOKEN` in the APK.** `android/app/build.gradle.kts` bakes `GATEWAY_ADMIN_TOKEN` into `BuildConfig` — extractable from any distributed APK, and the admin token owns worker registration/revocation and the full audit log. The companion app only ever needs the *owner* token (see #1); delete this BuildConfig field and have the app send only its paired owner token.

Bump as one maintenance pass (M); nothing exotic pins you down (no kapt, no Hilt).

## Missing gates (CI/tests/protection)

- **No CI at all** — `tests/test_gateway.py` (13 KB, covers routing/auth/idempotency) never runs automatically. Add a GitHub Actions workflow: `pytest` on push/PR + `gradle assembleDebug` for the Android module (S). This is the single highest-value gate: the repo's one real asset is the tested gateway, and nothing enforces it stays green.
- No branch protection on `main` (all branches `protected: false`) — require the CI workflow once it exists (S).
- No lint: add `ruff` (Python) and the default Android lint task to CI (S).

## Quick wins (code/config)

- `GatewayClient.create(baseUrl)` builds a bare `OkHttpClient` — no timeouts. Add connect/read timeouts (10s/30s) so a dead gateway doesn't hang the UI thread's coroutines forever (S).
- `db.py` default `:memory:` for the served app (`GATEWAY_DB` env) means every restart wipes workers/audit — fine for dev, but document it loudly in README and default systemd/docker examples to a file path (S).
- `Route` enum in Kotlin uses backticked `` `on-device` `` — fine, but keep the enum↔Python value mapping under a contract test; you already mirror models by hand, so a CI test that round-trips one job through the real gateway (httpx + TestClient) from the Kotlin DTO JSON would catch drift (M).
- `JobComplete`/`JobClaim` put `worker_token` in the **request body** — move to an `Authorization: Bearer` header for consistency with the admin header and to keep tokens out of any future request-body logging (S).
