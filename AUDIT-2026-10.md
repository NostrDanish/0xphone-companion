# Security Audit — NostrDanish/0xphone-companion — 2026-10-20

## Summary
Phase-1 prototype: FastAPI "secure task gateway" (policy engine + SQLite + audit log) with a Kotlin/Compose Android skeleton. The policy engine itself is well designed (secret-classified data may never leave the device; server-side capability checks on every claim; idempotent claims; append-only audit log; parameterized SQL; admin token from env, never hardcoded). **However, all client-facing endpoints — including the human-approval gate that releases internal/confidential jobs to remote workers — have NO authentication.** This is acceptable only while the service binds to loopback for emulator testing; the stated plan to reach the gateway over a tunnel would make the approval-bypass CRITICAL. No hardcoded secrets found anywhere in the repo.

Findings: 0 CRITICAL / 1 HIGH / 3 MEDIUM / 1 LOW (PC-01 escalates to CRITICAL if the gateway is exposed beyond loopback)

## Findings
| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| PC-01 | HIGH (CRITICAL if tunnel-exposed) | gateway/app.py — POST /jobs, GET /jobs/{id}, POST /jobs/{id}/cancel, POST /jobs/{id}/approve | None of the client/job endpoints require any credential. In particular `/jobs/{id}/approve` is the human-in-the-loop control that moves `awaiting_approval` jobs (internal/confidential data) to `remote_worker` — anyone with network access can self-approve exfiltration of non-public data, submit arbitrary jobs, or cancel any job. | Add an authenticated "device owner" principal (token or mTLS client cert) required for submit/read/cancel/approve; keep worker tokens for claim/complete; bind approvals to the on-device user. |
| PC-02 | MEDIUM | gateway/app.py — GET /jobs/{job_id} | Unauthenticated read returns full job record incl. `result` payload. job_ids are 64-bit random (unguessable-ish) but leak via logs/referrers; no defense in depth. | Require auth on reads; redact `result` for non-owner callers. |
| PC-03 | MEDIUM | gateway/app.py — require_admin | Single static bearer token from env, compared with `!=` (not constant-time), no rate limiting, no TLS anywhere in the design; README deployment model is plaintext HTTP. | Use `hmac.compare_digest`; add rate limiting; if tunnel-exposed, terminate TLS and put Cloudflare Access/mTLS in front. |
| PC-04 | MEDIUM | requirements.txt | All dependencies unpinned (`fastapi`, `uvicorn`, `pytest`, `httpx`) — non-reproducible installs, no supply-chain pinning. | Pin versions (e.g. `fastapi==x.y.z`) and add a lockfile + hashes (`pip-tools`/uv). |
| PC-05 | LOW | gateway/db.py, app.py | Worker tokens and claims stored plaintext in SQLite (acceptable at rest on-device, but DB file leak = full impersonation); `revoke_worker` re-returns the worker token; paid-model route reuses the `worker_token` request field as the admin token (confusable credential channel). | Hash worker tokens (e.g. SHA-256) at rest; don't echo tokens after creation; separate admin auth from worker-token fields. |

## Secrets Check
Scanned (manual review; GHAS secret scanning not enabled on repo): gateway/app.py, policy.py, db.py, models.py, requirements.txt, README.md, SPEC.md, android/ skeleton. **No hardcoded secrets found.** Admin token is read from `GATEWAY_ADMIN_TOKEN` env; README correctly instructs `local.properties` / env and "never commit it" (the `dev-token` string in README is a placeholder example, not a live credential).

## Dependency Notes
fastapi / uvicorn / pytest / httpx, unpinned (see PC-04). No known-vulnerable pinned versions to flag (none are pinned at all). Stdlib sqlite3 — no ORM injection surface; all queries parameterized (verified).

## Fork/Upstream Freshness
Not a fork — original code. N/A.

## Recommended Actions
1. [PC-01] Before ANY tunnel/LAN exposure: add owner authentication to /jobs submit/read/cancel/approve. Treat as release-blocker.
2. [PC-03] hmac.compare_digest for token checks; document TLS/mTLS requirement for remote access; consider mutual-TLS via cloudflared + Access.
3. [PC-04] Pin dependencies; add pip-audit to CI.
4. [PC-02] Authenticate job reads; avoid returning `result` to unauthenticated callers.
5. [PC-05] Hash worker tokens at rest; split admin vs worker credential fields.
6. Keep the excellent policy-engine invariants (secret never leaves device) covered by the existing 19 tests as endpoints gain auth.
